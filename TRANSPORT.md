# Native transport contract

The runtime boundary copies bytes and error text. Structured SDK operations use
protobuf envelopes, scalar identifiers use fixed-width binary values and headers
are opaque Temporal payload maps. Neither application Go objects nor protobuf
metadata pointers cross owners.

## Framing

Startup request/reply prepends ASCII `ISOL`, then four little-endian uint32
values: protocol 7, compiler metadata 1, API 1 and determinism 1. The header is
20 bytes and must be checked before startup body decoding or factory execution.
Other operations use their own message bodies, not an automatic startup header.
Identifier-only numeric requests are exactly eight bytes, uint64 little-endian;
reject any other length. String identifiers are raw UTF-8 bytes. MarshalTransport also encodes int,
uint64 and Version as eight little-endian bytes (signed values use their int64
two's-complement bit pattern) and bool as a one-byte 0/1 value. Observation
LogWrite is 0xffff0002 and MetricWrite is 0xffff0003; runtime LogOp is 0xffff0001. Runtime
`OpSleep` uses a decimal signed duration in nanoseconds. Session recreation tokens
retain the session protocol's token format. Observation operation numbers are
reserved separately by their sink/log APIs.

Transport errors from `Command.Reply` copy diagnostic text. SDK operation errors
that need concrete identities/details are represented by typed failure envelopes
and explicit error tags. Successful scheduling replies are distinct from later
completion replies. Late replies after definition close are retired.

`OpStartPayloads` carries PayloadStart after header validation; completion uses
PayloadCompletion. ScheduleActivity/Child/Local/Nexus/External use their request
messages; corresponding await/cancel operations use IDs and their outcome or
execution replies. Handler registration/delivery/completion uses the query,
update and signal messages. Metadata/visibility messages use WorkflowInfo,
PayloadFields and canonical attribute entries. The retained byte-handler APIs
use Start/Completion/ActivityRequest/Signal input fields. Empty operation bodies
and boolean/status replies follow their API operation, rather than inventing an
empty application Payloads value. See workflow/temporalbridge operation files
for dispatch and [SDK_REFERENCE.md](SDK_REFERENCE.md) for operation semantics.

## Message schema

This is the complete current generated schema. Field numbers/types, including
options and nested Temporal payload/header/failure messages, are part of the
paired host/workflow contract. Signed Go integers/durations use sint64; durations
are nanoseconds. Timestamps use google.protobuf.Timestamp. Integer conversions
reject range/sign overflow. VersioningOverride.Kind is `pinned`, `auto` or `once`;
unknown variants reject. Nil pointer option messages preserve absence. Standard
Temporal common/failure definitions come from pinned go.temporal.io/api.

## Generation and validation

The generator inventories shared Go envelope/options types, builds protoc-gen-go
from the pinned module, obtains imported descriptors from pinned modules, emits
the schema/bindings and static conversions for both directions. It does not need
a separate Temporal proto checkout. Change the shared types/generator together;
never hand-edit generated bindings.

```sh
GO=/absolute/path/to/golang-go/bin/go python3 internal/cmd/transportgen/generate.py
tgo test ./workflow ./temporalbridge ./internal/integrationcontract
```

Review this schema/operation reference whenever regeneration changes it. Tests
cover malformed identifiers/headers, overflow, presence, payload/failure round
trips, options forwarding and replay. The wire envelope is internal transport;
durable application encoding remains the selected DataConverter/codecs contract.
